# AGENTS.md — Правила проекта Velum

## Общие принципы

- **Простота прежде всего.** Старайтесь сделать задачу максимально простой. Не усложняйте там, где не нужно.
- **Факты важнее предположений.** Не галлюцинируйте. Проверяйте факты, прежде чем предоставлять информацию.
- **Действуйте, а не только описывайте.** При создании или изменении кода всегда используйте инструменты для реальных изменений в файлах.

## Протокол отладки — [`DEBUG_CASEBOOK.md`](DEBUG_CASEBOOK.md)

Рядом с этим файлом лежит **протокол разобранных ошибок** проекта: симптом → гипотезы (включая тупиковые) → корень → исправление → эвристики.

- **Прежде чем искать причину бага — прочитайте `DEBUG_CASEBOOK.md`** (разделы «Эвристики» и «Указатель случаев»). Если симптом похож на описанный, начинайте с уже известного корня, а не с обхода кодовой базы. Заведомо тупиковые ветки из протокола **не повторять**.
- **После каждого успешно исправленного бага — добавьте случай** в `DEBUG_CASEBOOK.md` по шаблону из того же файла (включая отменённые неудачные гипотезы) и, если правка обобщается, новую эвристику. Это обязательная часть работы наравне с обновлением справки.

## Компиляция

Корень проекта — `D:\Программы\VELUM\Velum`, файл проекта — **`velum.csproj`** (строчная `v`; `Velum.csproj` не существует).

**Сборка из коробки (предпочтительно):**

```powershell
.\Build.cmd Debug          # либо .\Build.cmd Release
```

`Build.cmd` вызывает `tools\Build-Velum.ps1`: он находит MSBuild через `vswhere` и **перед** velum собирает `..\ISIDA\Programms\app\SymbiontEnv.Contract\SymbiontEnv.Contract.csproj` в той же конфигурации.

**Прямой запуск MSBuild** (путь актуален для установленного VS 2022 Professional; надёжнее получать его `vswhere -latest -requires Microsoft.Component.MSBuild -find MSBuild\**\Bin\MSBuild.exe`):

```bash
MSB='/c/Program Files/Microsoft Visual Studio/2022/Professional/MSBuild/Current/Bin/MSBuild.exe'
"$MSB" velum.csproj -t:Build -p:Configuration=Debug -v:m -nologo -clp:ErrorsOnly; echo "EXIT=$?"
```

- **Не используйте** `dotnet build` — проект не поддерживает .NET SDK для сборки.
- **Не используйте** команду `msbuild` без полного пути — она не в PATH.
- **Не запускайте** `cmd /c Build.cmd` из bash-окружения — cmd зависает; используйте прямой вызов MSBuild выше либо `powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Velum.ps1 Debug`.
- Конфигурации: только `Debug|AnyCPU` и `Release|AnyCPU`; внешние зависимости собираются в ту же конфигурацию (см. «Внешние сборки»).

## Внешние сборки (пути к ссылкам)

`Velum` лежит **рядом** с `ISIDA` (`D:\Программы\ISIDA`), поэтому все ссылки — на **один** уровень вверх:

| Ссылка | `HintPath` в `velum.csproj` |
|--------|------------------------------|
| `isida` | `..\ISIDA\Programms\isida\bin\$(Configuration)\isida.dll` |
| `SymbiontEnv.Contract` | `..\ISIDA\Programms\app\SymbiontEnv.Contract\bin\$(Configuration)\SymbiontEnv.Contract.dll` |
| `Newtonsoft.Json` 13.0.3 | `..\ISIDA\Programms\isida\packages\Newtonsoft.Json.13.0.3\lib\net45\Newtonsoft.Json.dll` |
| `SolidWorks.Interop.*`, `Xarial.XCad.*` | `packages\...` (NuGet, см. `packages.config`) |

- **Никогда не `..\..\ISIDA\...`** — два уровня вверх ведут на `D:\ISIDA`, которого нет; такие пути появились от старого расположения репозитория (`D:\VELUM\Velum`) и ломают сборку (цели `EnsureIsidaBuilt`, `EnsureSymbiontEnvContractBuilt`).
- После `CopyFilesToOutputDirectory` цель **`CopyIsidaRuntimeAssemblies`** копирует все `*.dll` из `..\ISIDA\Programms\isida\bin\$(Configuration)\` в выход Velum — дублировать логику ядра агента в velum нельзя.
- Перед сборкой Velum нужны актуальные сборки `isida` и `SymbiontEnv.Contract` в **той же** конфигурации.
- Список DLL в **`installer\VelumSetup.iss`** должен совпадать с выходом `bin\Debug` / `bin\Release` после полной сборки (`isida.dll` и спутники попадают туда из выхода isida); при новых зависимостях isida обновите секцию `[Files]`.

## Регистрация файлов в проекте (`velum.csproj`)

Проект **не SDK-style**: MSBuild **не** подхватывает `*.cs` и соседние файлы автоматически. Любой новый исходник, ресурс или артефакт сборки нужно **вручную прописать** в `velum.csproj`, иначе он не войдёт в сборку (CS0246 «тип не найден», типы «не видны» в IDE). Переименование/удаление файла — **синхронно** править в `csproj`.

- **Новый класс:** `<Compile Include="ReactiveCore\MyClass.cs" />` в соответствующем `<ItemGroup>` (группировать по папкам, как у `Configuration\`, `Common\`, `ReactiveCore\`).
- **Форма WinForms** — три артефакта одновременно:

| Файл | Узел в `velum.csproj` |
|------|------------------------|
| `MyForm.cs` | `<Compile Include="…\MyForm.cs"><SubType>Form</SubType></Compile>` |
| `MyForm.Designer.cs` | `<Compile Include="…\MyForm.Designer.cs"><DependentUpon>MyForm.cs</DependentUpon></Compile>` |
| `MyForm.resx` | `<EmbeddedResource Include="…\MyForm.resx"><DependentUpon>MyForm.cs</DependentUpon></EmbeddedResource>` |

- **Частичный класс-«спутник»** (`.Metrics.cs`, `.ExportHub.cs`): `<Compile>` с `<DependentUpon>` основной формы/класса и тем же `SubType`.
- **Картинка для команд XCad / `Resources.*`:** `ResXFileRef` в `Properties\Resources.resx` + свойство в `Resources.Designer.cs`.
- **Файл рядом с `velum.dll`:** `<Content Include="icons\…"><CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory></Content>`; при необходимости продублировать в `installer\VelumSetup.iss` (`Source: "{#BuildBin}\icons\…"`).

**Чеклист перед концом задачи:** (1) каждый новый/переименованный файл указан в `velum.csproj`; (2) сборка проходит, нет CS0246 из-за забытых `Include`; (3) удалённые с диска файлы убраны из `velum.csproj`.

## XML-комментарии

- **Обязательные XML-комментарии (`///`)** — для каждого публичного/внутреннего типа, метода, свойства, поля, события, интерфейса, **включая конструкторы** открытых типов и `protected override` (например `Dispose(bool)` в Designer).
- **Ошибка CS1591 уже включена** в `.csproj` (`<WarningsAsErrors>1591</WarningsAsErrors>`) иDocumentationFile. Компиляция без комментариев не проходит.
- Пишите XML-комментарии **сразу** при написании/изменении кода, не откладывайте. Используйте `<summary>`, `<param>`, `<returns>`.
- **`<see cref="…"/>`** — только на типы и члены, которые генератор документации **разрешает из метаданных** ссылок проекта, иначе **CS1574**.
  - Методы **COM / `SolidWorks.Interop`** часто не разрешаются в `cref` → имя метода давать в **`<c>ИмяМетода</c>`**, при необходимости ссылаться только на тип: `<see cref="Sketch"/>`.
  - То же для членов, доступных только через `dynamic` / `InvokeMember` или отличающихся между версиями PIА.
  - При неоднозначных перегрузках указывать **полную ECMA-ссылку** (`M:Namespace.Type.Method(...)`) — иначе **CS0419**.

## Архитектура Velum + ISIDA

- **Данные и настройки Velum** — под `%ProgramData%\VELUM\` (`help`, реестры, кэш). Пути и параметры ISIDA — из **`Velum.Configuration.VelumAppConfig`** (`Velum.Settings.xml`).
- Пульсация: только через **`ISIDA.Common.GlobalTimer`** после `IsidaEngine.Create`; стадия эволюции для запуска пульса ≥ 1.
- **Давление метрик среды на P_i** — `docs\SOLID_METRIC_PRESSURE.md`, оркестратор `SolidHomeostasis\VelumSolidMetricPressureOrchestrator.cs`; план обучения — `docs\Stage2_Training_Plan.md`.
- **COM SolidWorks** и вызовы API модели — в потоке UI процесса SW; события `GlobalTimer` маршалить на UI через `Control.BeginInvoke` / контекст окна, а не обращаться к UI из произвольного пула потоков.

## SolidWorks PIА / COM (`SolidHomeostasis\**`)

В проекте используются `SolidWorks.Interop.sldworks` и `SolidWorks.Interop.swconst` из пакета **Xarial.XCad.SolidWorks 0.8.1** (`net461`, PIA **32.x**), тогда как хост часто **SW 2019**. **Число параметров**, `ref`/`out` и **имена перечислений** могут расходиться с Web Help и с PIA «с диска»: проверять по метаданным своей ссылки (рефлексией), а не по памяти.

- **`PartDoc.GetMaterialPropertyName2`** — фактическая сигнатура: `string GetMaterialPropertyName2(string configurationName, out string databaseName)`; имя материала — **возвращаемое значение**, база — `out`. Варианты `out`/`out`, `ref`/`ref` и «лишняя» 4-я перегрузка → **CS1615 / CS1620**.
- **`PartDoc.SetMaterialPropertyName2`** — `void SetMaterialPropertyName2(string configurationName, string databaseName, string materialName)`; второй аргумент — база (`имя.sldmat` или путь), значение из `Get…` часто **без** `.sldmat` — нормализовать перед записью. Эталон: `SolidHomeostasis\MetricProbes\VelumSolidWorksMaterialComHelper.cs`.
- **`swconst`**: имена вроде `swConfigurationOption_e` / `swConfigurationOptions_e`, член `swThisConfiguration` в разных DLL различаются или отсутствуют. Нужен числовой код из документации — **константа `int` с комментарием**, а не догадка об имени enum.
- **`CustomPropertyManager.Get6`** на части установок даёт **`AccessViolationException`** (обычный `catch` в .NET 4+ не ловит) — читать через `Get2`, при сбое `Get`; **`Get6` не вызывать** (`ReactiveCore\VelumRecipeSolidWorksCustomProperties.cs`).
- `dynamic` по COM для отсутствующих в PIA членов даёт `RuntimeBinderException` — предпочитать `InvokeMember` и явные типы (`SolidHomeostasis\VelumSolidComDispatchHelper.cs`).

## WinForms

- **Разметка форм** (панели, вкладки, кнопки, `DataGridView`, подписи) — в **`*.Designer.cs`** через `InitializeComponent()`, чтобы форму можно было открыть в конструкторе. В **`*.cs`** — привязка данных, обработчики, валидация, вызовы ISIDA. Динамическое создание контролов — только для временных диалогов.
- **Конструктор не открывается**, в стеке `VSCodeDomParser` / `TypeCodeDomSerializer` — почти всегда из‑за **`nameof(ВложенныйТип.Свойство)`** в `InitializeComponent`, когда тип объявлен в **другом** файле partial-класса, либо из‑за `var` / тяжёлых object initializers в том же методе.
  - Для `DataPropertyName`, имён колонок и прочих строк привязки — **обычные строковые литералы** (`"ParameterLabel"`), а не `nameof(...)`.
  - Колонки `DataGridView` — явным типом и пошаговыми присвоениями, без `var` и громоздких инициализаторов.
  - Не путать с обычными ошибками компиляции (видны в Error List) и с отсутствием файла в `velum.csproj`.
- **Подписи и ToolTip**: термины гомеостаза — **P_i** (параметр самоподдержания), **T_i** (критические пороги), **N_i** (нормативная граница; в UI «норма N_i»), **BS** (стиль поведения), **EA** (элементарное компенсаторное воздействие оператора), **G_AD** / «адаптивные действия» (вариабельные стратегии компенсации; не смешивать с «AD» = адаптивный контур). Подпись — короткий русский термин + обозначение в скобках. ToolTip — 1–2 предложения: что делает элемент, в каких терминах; при записи данных — куда (`%ProgramData%\VELUM\…` / подсистема ISIDA); при редактировании КБ — напоминание об ограничениях (**стадия эволюции 0**, **пульсация остановлена**). Образец тона: `Common\VelumProjectSettingsForm`.

## Типовые таблицы-редакторы справочников

При создании или доработке формы-редактора данных в виде таблицы (`DataGridView`). **Ориентир в коде:** `Common\DocumentProperties\VelumDocumentPropertyBatchForm.cs` + `.Designer.cs` (таблица, фильтр с «Применить»/сбросом, ToolTip'ы кнопок и колонок, подтверждения опасных действий), `Common\VelumListFilterHelper.cs` и `Common\VelumListViewCellFilterMenu.cs` (фильтрация списков), справка `docs\help\shared\list-filters.html`. Точка входа для просмотра паттернов, а не шаблон для буквального копирования.

**Кнопки и сохранение**

1. Обязательны **«Добавить»**, **«Сохранить»** (с валидацией) и **«Очистить»** в смысле очистки всей таблицы (или явно «Очистить таблицу», если рядом сброс фильтров).
2. Очистка таблицы — только после **модального подтверждения** (Yes/No). Правил валидации нет в коде/документе — **уточнить у постановщика до работы**.
3. Новая запись — осмысленные значения по умолчанию («Новая запись …», числа в допустимом диапазоне); дефолты неочевидны — уточнить.
4. После «Добавить» переводить фокус на новую строку (выделение, `CurrentCell`, прокрутка).

**Удаление**

5. Удаление одной или нескольких выбранных записей (Delete, контекстное меню) — **только** через подтверждение с указанием количества; при «Отмена» — ничего не удалять.
6. Если удаление идёт только своим кодом — `AllowUserToDeleteRows = false` (при необходимости и `AllowUserToAddRows = false`), чтобы не было «тихого» удаления мимо подтверждения.

**Фильтры**

7. Панель фильтров — по **нескольким** полям (перечень согласовать); логика по умолчанию — поиск по вхождению подстроки без учёта регистра, непустые условия объединяются по **И**.
8. Применение — по кнопке **«Применить»**, не пересчитывать на каждый символ. Сброс условий — по своей кнопке с однозначной подписью.
9. У кнопок «сброс фильтра» и «очистить таблицу» — **разные** подписи и ToolTip.

**Таблица**

10. Заголовкам столбцов задавать всплывающие подсказки (`ToolTipText` столбца или общий `ToolTip`).
11. Клик по заголовку — **сортировка** с переключением направления; для `BindingList` — режим **Programmatic** и явная перестановка строк в источнике.
12. После сортировки / перезагрузки / добавления строки при активном фильтре обновлять **видимость строк**.
13. `DataError`: по умолчанию `e.ThrowException = false`, при необходимости логировать.
14. Сложные поля (многострочный текст, списки ID, выбор из справочника) — двойной щелчок / отдельная модальная форма, а не обязательная правка «в ячейке».

**Модальность**

15. Модальный редактор из надстройки: `ShowInTaskbar = false`, `StartPosition = CenterParent`, `MinimizeBox = false`; `CancelButton` — основная кнопка отмены, если это предполагает UX.
16. При несохранённых изменениях и закрытии — предупреждение «Сохранить / не сохранять / отмена» (или явное согласование, если образца нет).

## Справка и документация пользователей

### Где находится справка

Справка Velum находится в `docs\help\` (проект) и копируется в `C:\ProgramData\VELUM\help\` (цель `CopyVelumHelp` в `velum.csproj` делает это автоматически при сборке). Файлы одинаковые — при ручной правке одной копируйте в другую.

Формы описаны в `docs\help\forms\` — по одному HTML-файлу на окно/форму.

### Обязательное обновление справки

**После каждого изменения, которое:**

- **Меняет алгоритм адаптера** — логику индексации, синхронизации свойств, классификации файлов, фильтрации, проверки путей и т.д.
- **Меняет интерфейс формы** — добавляет/удаляет/переименовывает элементы управления, кнопки, поля, меню, контекстные меню, всплывающие подсказки.
- **Меняет поведение формы** — новый диалог, новый результат операции, новое сообщение об ошибке/успехе.

**Необходимо:**

1. **Найти** соответствующую страницу справки в `docs\help\forms\`.
2. **Обновить** описание на странице, чтобы оно отражало новые изменения — выдерживая стиль изложения и оформления.
3. **Скопировать** обновлённую страницу в `C:\ProgramData\VELUM\help\forms\`.
4. **Если страницы нет** — создайте её, если изменения действительно стоит показать пользователю (не всё подряд, а то, что пользователь должен знать).

### Стиль справки

- HTML-файлы используют `styles.css` — совместимо с IE/WebBrowser (без flex/grid).
- Структура: `<h1>` — название окна, `<h2>` — разделы, `<ul>`, `<ol>`, `<table>` для списков и таблиц.
- `.note` — блок-примечание (синий фон, синяя полоса слева).
- `.warn` — блок предупреждения (жёлтый фон, жёлтая полоса слева).
- `.figure` — изображение с подписью (`.caption`).
- `.seealso` — блок "См. также" в конце страницы.
- `.meta` — дополнительная информация (окно, раздел).
- Код — через `<code>`, блоки кода — через `<pre><code>`.
- Ссылки на другие страницы справки — относительные пути (`../shared/list-filters.html`, `assembly-registry.html`).
- Язык — **русский** (страницы справки на русском языке).

## Проверка существования файлов

- **В коде, выполняющемся в UI-потоке SolidWorks** (обработчики событий SW, обработчики кнопок форм/панели, такты пульсации, всё, что идёт через `RunOnTaskPaneUiThread` / `BeginInvoke` окна SW), **запрещено** вызывать `File.Exists` / `Directory.Exists` напрямую. Использовать **`VelumPathExists.FileExists(path)`** / **`VelumPathExists.DirectoryExists(path)`** (`Common\VelumPathExists.cs`) — они выполняют проверку с жёстким таймаутом (`Task.Run` + `Wait`/`Result`), по истечении которого путь считается несуществующим (для недоступного сетевого тома `File.Exists` вешает UI SolidWorks на десятки секунд).
- **Исключение:** фоновые ThreadPool-сканеры реестра (`Common\ProductRegistry\Integrity\*`, `QueueTick`-циклы), которые уже используют `Task.Run`/`Wait` с таймаутом (см. `VelumProductRegistryPathChecker`). В них прямой `File.Exists` внутри фоновой задачи допустим — UI он не блокирует.
- **Не использовать** `VelumPathExists` в циклах по тысячам записей без предварительной фильтрации: каждый вызов — это задача в пуле потоков; массовые проверки путей — через `Directory.EnumerateFiles` + `HashSet` или пакетный проход сканера.
- При появлении новой проверки пути в коде UI-потока — сразу `VelumPathExists.*`, сборка MSBuild, и страница справки — если поведение меняется для пользователя.

## Работа с файлами: доступные инструменты

**Не** вызывать несуществующие инструменты (`GlobTool`, `ReadFile`, `SearchFileTool`, `EditFileTool`, `grep`, `rg`, `find` и т.п.) — их нет в реестре, повторные вызовы приводят к зацикливанию. Для всех операций с файлами использовать **только** следующие инструменты:

| Задача | Инструмент | Параметры |
|--------|------------|-----------|
| Список файлов/папок в каталоге | `list_directory` | `path` (абсолютный), опц. `ignore` |
| Чтение одного файла (текст, изображение, PDF) | `read_file` | `absolute_path`, опц. `offset`+`limit` |
| Чтение нескольких файлов / по glob-маскам | `read_many_files` | `paths` (массив), `include`, `exclude` |
| Поиск по **содержимому** (regex) | `search_file_content` | `pattern`, опц. `path`, `include` |
| Поиск файлов по имени/маске | `glob` | `pattern`, опц. `path` |
| Запись/создание файла целиком | `write_file` | `file_path`, `content` |
| Точечная замена фрагмента в файле | `replace` | `file_path`, `old_string`, `new_string`, опц. `expected_replacements` |
| Выполнение shell-команды | `run_shell_command` | `command`, опц. `directory`, `timeout` |
| Web-поиск / документация | `google_web_search`, `docs_search`, `web_fetch` | — |

**Правила, чтобы не зацикливаться:**

1. **Перед правкой — сначала `read_file`** целевого участка (минимум 3 строки контекста вокруг правки) и **`search_file_content`**, чтобы найти все места. Не строить догадок о содержимом файлов.
2. **Для точечной правки** использовать `replace` с точным `old_string` (включая отступы и переносы). Для нового файла / полной перезаписи — `write_file`.
3. **Если инструмент «не найден»** — это значит, такого инструмента нет. Не пытаться повторить тот же вызов: немедленно выбрать доступный из таблицы выше.
4. **Параллельные независимые вызовы** (несколько поисков/чтений) можно запускать в одном сообщении, чтобы не тратить шаги.
5. После изменения кода — прогнать **сборку** (`.\Build.cmd Debug`) и **проверки** проекта (см. «Компиляция»).
