Экспорт BOM в 1С

Формирование CSV-файлов обмена с 1С: карточки номенклатуры (состав и отслеживаемые свойства компонентов, например «Материал», «Масса») и структура состава сборок с операциями добавления, изменения и удаления строк.

Окно: «Экспорт BOM в 1C» · раздел: bom-exchange

Как открыть

Через conditioned-рефлекс «Обмен BOM с 1С» (рецепт bom_exchange_show_dialog, действие среды ID 48). Окно открывается, когда срабатывает связанное с ним действие среды — например, при расхождениях BOM. Прямого пункта на ленте нет.

Как это работает

Обмен разделён на два независимых потока, которые выгружаются раздельно:

  • Карточки номенклатуры — Velum при каждом сохранении детали или сборки запоминает состав и значения отслеживаемых свойств в локальном зеркале (%ProgramData%\VELUM\AssemblyRegistry\bomMirror.json). При изменении свойств или количества позиция помечается как «расхождение». В файл карточек попадают только позиции с расхождениями и заполненным идентификатором связи с 1С.
  • Структура состава — при каждом сохранении сборки (файл .sldasm) Velum запоминает состав её прямых компонентов (без вложенных сборок) в bomStructure.json и фиксирует операции над строками состава (add — компонент добавлен, update — изменилось количество или идентификатор связи, delete — компонент удалён) в журнале bomChangeLog.json. Структура каждой вложенной сборки строится при её собственном сохранении.
Структура состава собирается только при сохранении сборки. После установки обновления файл bomStructure.json пуст: структура каждой сборки появится при её первом сохранении, и первая выгрузка по ней будет содержать полный состав (операции add).
Строка состава выгружается, только если у родителя (сборки) заполнено свойство ExternalId. Если оно пустое — структура этой сборки не запоминается и не выгружается.
При сохранении детали или сборки Velum автоматически заполняет пустое свойство ExternalId именем файла. Берётся финальное имя, под которым файл записан на диск (предложенное автопоиском имя могло быть изменено в диалоге сохранения). Уже заполненное значение не перезаписывается.

Элементы окна

ЭлементЧто делает
Каталог обмена Сетевой или локальный каталог, куда записываются CSV-файлы. Значение сохраняется в настройках проекта (кнопка Обзор выбирает каталог).
Вкладка «Карточки» Список позиций с расхождениями свойств. Состав, порядок и заголовки столбцов берутся из настроек выгрузки (кнопка Поля…) и совпадают со столбцами файла 1C_update_*.csv.
Вкладка «Структура» Список строк состава, ожидающих выгрузки: родитель, компонент, конфигурация, количество и действие (add/update/delete). Совпадает со строками файла 1C_bom_*.csv.
Статусная строка Показывает, сколько карточек и строк состава ожидает выгрузки.
Настройки Открывает окно «Отслеживаемые свойства BOM» — список свойств, изменения которых отслеживаются.
Поля… Открывает окно «Поля выгрузки BOM» — настройка состава, порядка и заголовков столбцов выгрузки карточек. Изменения сразу применяются к таблице и к CSV. Столбцы файла структуры фиксированы и не настраиваются.
Экспорт Формирует CSV-файлы обмена: карточки (1C_update_*.csv) и структуру (1C_bom_*.csv). Каждый файл создаётся, только если есть что выгружать. После успешной записи расхождения сбрасываются.
Закрыть Закрывает окно без экспорта.
Кнопка Экспорт активна, только если указан каталог обмена.

Файл карточек: 1C_update_ГГГГ.ММ.ДД.ЧЧ.ММ.СС.csv

Кодировка UTF-8 с BOM, разделитель — точка с запятой. Состав и порядок колонок задаются в окне «Поля выгрузки BOM» и по умолчанию равны:

  • TypeDocs — тип документа: Assembly (сборка) или Part (деталь);
  • ExternalId — идентификатор связи с 1С (свойство компонента в SOLIDWORKS; при сохранении заполняется именем файла, если поле пустое, и может быть изменён вручную);
  • Designation, Name — обозначение и наименование;
  • FilePath, Configuration — путь к файлу и конфигурация;
  • Quantity — количество вхождений;
  • далее — отслеживаемые свойства (настраиваются отдельно).
Позиции без заполненного свойства ExternalId в файл обмена не попадают.

Файл структуры: 1C_bom_ГГГГ.ММ.ДД.ЧЧ.ММ.СС.csv

Кодировка UTF-8 с BOM, разделитель — точка с запятой. Колонки фиксированы (последняя — операция):

ParentExternalId;ParentConfiguration;ChildExternalId;ChildConfiguration;Quantity;Action
  • ParentExternalId, ParentConfiguration — идентификатор связи с 1С и конфигурация сборки-родителя;
  • ChildExternalId, ChildConfiguration — идентификатор связи с 1С и конфигурация компонента (конфигурация вхождения — та, что фактически использована в сборке);
  • Quantity — количество компонента в родителе (для операции delete — количество до удаления);
  • Action — операция: add, update или delete.

Строки отсортированы по родителю, затем по компоненту; операции одной пары идут в хронологическом порядке, поэтому 1С применяет их последовательно. Идентификатор связи компонента берётся актуальным на момент выгрузки (из зеркала карточек), а не на момент изменения.

Строки состава, у которых компонент не имеет заполненного свойства ExternalId, в файл не попадают: они остаются в очереди и будут выгружены, когда идентификатор появится.

Типовой порядок работы

  1. Сохраните сборки и компоненты — пустые свойства ExternalId заполнятся именами файлов, заполненные не изменятся, а Velum зеркалирует карточки и структуру состава автоматически.
  2. Укажите каталог обмена и при необходимости настройте список свойств и состав полей выгрузки карточек.
  3. Нажмите Экспорт и передайте файлы в 1С.

Данные на диске

Каталог %ProgramData%\VELUM\AssemblyRegistry:

  • bomMirror.json — зеркало карточек (состав и свойства);
  • bomStructure.json — структуры состава сборок;
  • bomChangeLog.json — журнал операций по строкам состава (невыгруженные записи хранятся до выгрузки; выгруженные — 10 дней);
  • bomTrackedProperties.json — список отслеживаемых свойств;
  • bomExchangeLayout.json — состав полей выгрузки карточек.

Каталог обмена хранится в настройках проекта.
