Диалоговые рецепты — оценка ответом среды

На стадии обучения (Stage 2) помощник запускает моторные действия (рецепты). После завершения мотора оценка полезности автоматизма выполняется ответом среды — по изменению состояния гомеостаза, а не по кнопкам формы.

Раздел: dialog-recipes · Механизм: Stage 2 Motor Outcomes

Как работает оценка

Когда помощник запускает мотор (через рецепт — диалог SW, макрос и т.п.), последовательность такова:

  1. Мотор — рецепт выполняется целиком (открытие диалога SW, настройка параметров, нажатие OK в SW и т.д.).
  2. Завершение мотора — Velum сообщает ISIDA: NotifyMotorCompleted(actionId). ISIDA переснимает «до»-состояние гомеостаза и перезапускает таймер ожидания.
  3. Ожидание — появляется форма-индикатор с обратным отсчётом. Симбионт ждёт изменения состояния среды.
  4. Оценка — при истечении таймера ISIDA сравнивает состояние «до» и «после»: улучшение → полезность растёт, ухудшение → падает, без изменения → нейтрально + рефрактерность.
Оценка по кнопкам формы (Apply / Forbid / Cancel) удалена — она противоречила архитектуре: кнопки нажимались до изменения состояния, а оценка не может быть раньше эффекта действия.

Форма-индикатор ожидания

После завершения мотора появляется небольшое немодальное окно с обратным отсчётом:

┌────────────────────────────────────────────┐
│  Действие: Захватить деталь (ID: 42)      │
│                                            │
│  Осталось пульсов: 12                      │
└────────────────────────────────────────────┘
  • Нет кнопок оценки — только индикация.
  • Показывает, что симбионт ждёт ответа среды.
  • Эффект действия оператора в этом окне интерпретируется как оценка.
  • Скрывается при истечении таймера или смене документа.

Пульт Поощрить / Наказать

Кнопки пульта (Поощрить / Наказать) остаются как дополнительный канал — принудительное перебивание оценки. Если оператор нажал Поощрить в окне ожидания, это перебивает оценку среды:

ДействиеЭффект
ПоощритьПолезность принудительно +
НаказатьПолезность принудительно −
Нет ответа (истечение таймера)Оценка по дельте состояния среды

Запрет у-рефлекса (dual-use)

Если мотор запущен от условного рефлекса и открывает диалоговую форму SW (например, экспорт DXF/PDF), на форме может быть кнопка «Запрет». Эта кнопка понижает крепость рефлекса, а не оценивает автоматизм:

  • Кнопка активна только если мотор запущен от у-рефлекса.
  • Нажатие → ResetAssociationStrengthToInitial — сброс крепости у-рефлекса.
  • Оценка автоматизма при этом идёт отдельно — ответом среды.

Архитектура контура

RecipeDispatcher
  ├→ RecipeExecutor.TryExecute(recipe)     — мотор выполнен
  ├→ AdaptiveActionsSystem.NotifyMotorCompleted(actionId)
  │    └→ AutomatismResultTracker.NotifyMotorCompleted(atmzId)
  │         ├→ StateBeforeOperatorImpact = CurrentOverallState
  │         ├→ CaptureOperatorEvaluationParameterSnapshot()
  │         └→ StartWaitingForOperatorEvaluation(atmzId)
  └→ VelumWaitingIndicatorForm.Show()       — плашка с отсчётом
       │
       └→ истечение таймера (ответ среды)
            └→ PsychicSystem.ResetAutomatizmWaitingState
                 └→ FinishTracking → AnalyzeResult
                      ├→ PreviousState vs CurrentState
                      └→ UsefulnessDelta → AfterAutomatizmUsefulnessUpdated
