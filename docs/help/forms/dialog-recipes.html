Диалоговые рецепты — оценка ответом среды

На стадии обучения (Stage 2) помощник запускает моторные действия (рецепты). После завершения мотора оценка полезности автоматизма выполняется ответом среды — по изменению состояния гомеостаза, а не по кнопкам формы.

Раздел: dialog-recipes · Механизм: Stage 2 Motor Outcomes

Как работает оценка

Когда помощник запускает мотор (через рецепт — диалог SW, макрос и т.п.), последовательность такова:

  1. Запуск мотора — автоматизм выбран и активирован. В этот же момент открывается окно ожидания («Ожидание оценки: N» в шапке панели «Агент») и начинается обратный отсчёт пульсов. Окно обслуживает две задачи сразу: ответ оператора с пульта и отклик среды.
  2. Мотор — рецепт выполняется целиком (открытие диалога SW, настройка параметров, нажатие OK в SW и т.д.).
  3. Завершение мотора — Velum сообщает ISIDA: NotifyMotorCompleted(actionId). Окно при этом не перезапускается: ISIDA только фиксирует факт завершения мотора. С этого момента разрешена оценка по реакции среды — пока диалог открыт, среда не могла отреагировать на действие, которого ещё не было.
  4. Ожидание — симбионт ждёт, пока метрика отпустит (например, «dxf устарел» перестанет быть плохой). Отсчёт продолжается с пульса запуска автоматизма.
  5. Оценка — как только состояние улучшилось (или ухудшилось), оценка выполняется сразу, не дожидаясь конца окна: улучшение → полезность растёт, ухудшение → падает. Если среда не отреагировала до истечения окна — автоматизм оценивается нейтрально (без изменения полезности), и окно закрывается.
Оценка по кнопкам формы (Apply / Forbid / Cancel) удалена — она противоречила архитектуре: кнопки нажимались до изменения состояния, а оценка не может быть раньше эффекта действия.

Почему отсчёт идёт от запуска, а не от завершения мотора

Окно одно, а задач у него две, поэтому отсчёт начинается при запуске автоматизма. Иначе оператор, который подумал 29 пульсов и только потом нажал «Экспорт», получал бы ещё полные 30 пульсов на ответ среды — то есть окно фактически удваивалось. Правило простое: сколько времени ушло у оператора, столько же осталось у среды.

Что произошлоКогда закрывается окноОценка
Мотор выполнен, метрика отпустила (среда отреагировала)Сразу, как только состояние улучшилосьПоложительная (полезность растёт)
Мотор выполнен, метрика ухудшиласьСразу при изменении состоянияОтрицательная (полезность падает)
Мотор выполнен, состояние не изменилосьПо истечении окна ожиданияНейтральная: полезность без изменения + короткая пауза, чтобы действие не повторялось подряд
Оператор закрыл диалог без выполнения («Отмена»/закрытие окна)Сразу при завершении мотораБез оценки: действия не было — оценивать нечего, полезность не меняется
Мотор провалился (ошибка рецепта)Сразу при завершении мотораБез оценки, действие не выполнено
Оператор ответил с пульта в пределах окнаПо ответу оператораОценка оператора (см. ниже)
Ни ответа оператора, ни реакции средыПо истечении окнаБез оценки, окно закрыто

Из таблицы видно: «оценки по факту запуска» нет. Пока мотор не завершился, оценка по среде заблокирована, а закрытый без выполнения диалог закрывает окно нейтрально — полезность автоматизма от этого не растёт.

Логи оценки

Каждый эпизод оценки виден в логах агента и в окне вывода панели (сокращённый лог «стимул → ответ»):

  • Начат период ожидания оценки оператора для автоматизма ID=…, длительность=N пульсов — окно открыто при запуске автоматизма. Если этой строки нет, окно не открылось, и оценки не будет.
  • ОЦЕНКА АВТОМАТИЗМА: ID …, по реакции среды, дельта=… — среда отреагировала, оценка выполнена.
  • ОЦЕНКА АВТОМАТИЗМА: ID …, по метрике на завершении мотора, дельта=… — состояние уже изменилось к моменту завершения мотора.
  • ОЦЕНКА АВТОМАТИЗМА: ID …, без оценки — <причина> — нейтральный исход (диалог закрыт без подтверждения, окно истекло).
  • Автоматизм N: полезность X → Y (дельта D) — факт изменения полезности; при без изменения автоматизм всё равно был оценён (нейтрально).

Индикатор ожидания

Отдельного окна нет: индикатор — это надпись в шапке панели «Агент»:

Ожидание оценки: 12      ← активное окно, N — осталось пульсов
Ожидание оценки: Нет     ← ожидания нет (серый текст)
  • Нет кнопок оценки — только индикация.
  • Появляется при запуске моторного автоматизма (стадия 2+), а не после завершения мотора.
  • Синий текст пульсирует, пока окно открыто; серый «Ожидание оценки: Нет» — когда ожидания нет.
  • Отсчёт привязан к глобальному пульсу, а не к таймеру интерфейса: темп отображения не «провисает».
  • Скрывается при истечении окна, оценке, смене документа и остановке пульсации.

Пульт Поощрить / Наказать

Кнопки пульта (Поощрить / Наказать) остаются как дополнительный канал — ответ оператора в пределах окна перебивает оценку среды:

ДействиеЭффект
ПоощритьПолезность принудительно +
НаказатьПолезность принудительно −
Нет ответа (истечение окна)Оценка по дельте состояния среды, если она изменилась; иначе без оценки

Ответом оператора считается не любое сообщение, а гомеостатическое воздействие с пульта (кнопки влияния). Если оператор ответил на последнем пульсе окна и оценка не успела выполниться — автоматизм закрывается нейтрально: окно не продлевается.

Запрет у-рефлекса (dual-use)

Если мотор запущен от условного рефлекса и открывает диалоговую форму SW (например, экспорт DXF/PDF), на форме может быть кнопка «Запрет». Эта кнопка понижает путь активации, а не оценивает автоматизм:

  • Кнопка активна только если мотор запущен от у-рефлекса (источник активации действия — условный рефлекс).
  • При рецепте от безусловного рефлекса или автоматизма кнопка недоступна — даже если в ISIDA остался ID у-рефлекса от прошлого эпизода (он только очищается).
  • Активация через сенсорный гейт (прекондиция: бедный стимул CS₁ открыл дорогу богатому CS₂ по выученной связи): наказывается сенсорная связь CS₁→CS₂, а не у-рефлекс — его нормальный точный стимул не страдает. Эффект штрафа: готовность связи понижается, связь требует повышенного порога для повторного открытия (гистерезис), а каждое операторское отклонение уменьшает будущий рост готовности (накопительный штраф). ISIDA: PenalizeLinkByOperator.
  • Обычная активация (точное совпадение пускового стимула): наказывается крепость у-рефлекса — ResetAssociationStrengthToInitial.
  • Подсказка кнопки показывает текущий параметр цели штрафа (готовность сенсорной связи или крепость У-рефлекса по памяти ISIDA); значение перечитывается при каждом наведении курсора и обновляется после сброса.
  • Оценка автоматизма при этом идёт отдельно — ответом среды.

Архитектура контура

PsychicSystem.ExecuteAutomatizm
  └→ AppGlobalState.StartWaitingForOperatorEvaluation(atmzId)
       ├→ StateBeforeOperatorImpact = CurrentOverallState
       ├→ CaptureOperatorEvaluationParameterSnapshot()
       └→ отсчёт окна от пульса запуска (индикатор: «Ожидание оценки: N»)
            │
            ├─→ опрос среды на каждом пульсе (только после завершения мотора)
            │    └→ AutomatismResultTracker.TryEvaluateWaitingByEnvironmentResponse
            │         └→ состояние изменилось → FinishTracking → UsefulnessDelta
            │
            ├─→ ответ оператора в пределах окна → MarkOperatorRecognition
            │
            └─→ истечение окна → PsychicSystem.ResetAutomatizmWaitingState
                 └→ FinishTracking → AnalyzeResult (нейтрально, если среда молчала)

RecipeDispatcher (Velum)
  ├→ RecipeExecutor.TryExecute(recipe)              — мотор выполнен
  ├→ AdaptiveActionsSystem.NotifyMotorCompleted(actionId, motorSkipped)
  │    └→ AutomatismResultTracker.NotifyMotorCompleted(atmzId, motorSkipped)
  │         ├→ MotorCompletedPulse = текущий пульс  — разрешает оценку по среде
  │         ├→ motorSkipped → закрыть без оценки
  │         └→ состояние уже изменилось → оценить сразу
  └→ индикатор в шапке панели (HideWaitingIndicator при смене документа/Стоп)

Таймеры ожидания

ТаймерНазначениеЗначение по умолчанию
A (Waiting)Единое окно ожидания оценки: ответ оператора и отклик среды. Отсчитывается от запуска автоматизма.Настройка «Ожидание оператора (пульс.)» на вкладке «Аналитика»; по умолчанию 30 пульсов
