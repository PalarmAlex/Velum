Моторные действия (handler'ы) и параметры

Мотор — это действие помощника в SOLIDWORKS. Каждое действие рецепта описывается handler'ом (командой исполнения) и его параметрами. Здесь перечислены доступные handler'ы, как задаются параметры и как помощник (психика) может сам менять числовые значения мотора через переменные психики {V:имя}.

Раздел: motor-handlers · Файл рецептов: %ProgramData%\VELUM\…\EnvironmentRecipes.yaml

Это не обязательное чтение для ежедневной работы. Раздел полезен, если вы настраиваете или обучаете помощника и хотите понять, какие действия он умеет и как задать им размеры/параметры.

Как устроен шаг рецепта

Рецепт состоит из шагов. Рабочий шаг имеет вид type: invoke и указывает handler — что делать — и набор параметров этого handler'а (плоские ключи рядом с handler):

- type: invoke
  handler: sketch_extrude_plate
  width: "100"
  height: "60"
  plane: front

Служебные поля type и handler зарезервированы; всё остальное — параметры конкретного handler'а. Строковый args в один рядок не поддерживается — параметры задаются отдельными ключами.

Команда SOLIDWORKS: почему параметры не через run_sw_command

Важно. run_sw_command запускает команду без параметров. В использованном интерфейсе SOLIDWORKS у метода запуска команды второй аргумент — это имя нового документа (NewTitle), а не набор параметров команды; отдельного «командного» метода с параметрами в нём нет. Поэтому параметрическую геометрию (пластины, отверстия и т.п.) помощник выполняет прямой последовательностью вызовов эскиза и операции, а не «командой с параметрами». Для пластины это handler sketch_extrude_plate.

Параметры-размеры: единицы и шаблоны

Числовые параметры геометрии задаются в миллиметрах (интерфейс SOLIDWORKS внутри работает в метрах — перевод выполняется автоматически). Значение параметра — это шаблон, в котором могут встречаться:

  • число — например "100" или "12.5" (точка или запятая как разделитель);
  • плейсхолдеры окружения — {DOCUMENT_PATH}, {FILE_NAME}, {DISCIPLINE}, {SEQ:n}, {FOLDER:n}, имена свойств документа (см. ниже);
  • переменные психики — {V:имя} (см. следующий раздел).

Плейсхолдеры окружения берут значение из текущего документа и пути к нему. Они пригодны и в текстовых параметрах (например, template у свойств), и в числовых (где после подстановки должно получиться корректное число).

Переменные психики {V:имя}: помощник сам меняет параметры

Плейсхолдер {V:имя} — это значение из реестра параметров мотора вида «идентификатор : значение», а не из документа и не из витал гомеостаза. Он позволяет одному и тому же мотору подставлять разные числа в зависимости от решения помощника — и менять эти числа без правки рецепта.

Как это работает:

  1. Рецепт хранит параметр как шаблон с именем переменной: width: "{V:ГабаритX}".
  2. Ментальный автоматизм (цикл мышления / правило реакции) записывает в реестр пару id → значение: "ГабаритX" → "120".
  3. При запуске мотора Velum берёт снимок реестра и подставляет значения в {V:...} каждого шага.

Так психика управляет параметрами команд отдельным, чистым каналом: реестр «id:значение» не смешивается с виталами и стилями гомеостаза (те описывают самочувствие агента, а не размеры детали).

Пример: мотор «пластина» с размерами из реестра психики

- type: invoke
  handler: sketch_extrude_plate
  width: "{V:ГабаритX}"
  height: "{V:ГабаритY}"
  depth: "{V:Толщина}"
  plane: front

Меняя значения ГабаритX, ГабаритY, Толщина в реестре, помощник сам подстраивает размеры пластины — текст рецепта при этом не трогается.

Статус. Запись в реестр из ментальных автоматизмов ISIDA — следующий шаг: сейчас реестр доступен из Velum (чтение/снимок для моторов), но движок ещё не пишет в него (нет готового API ментального действия с параметром). Пока реестр пуст, переменная не находится, токен {V:…} остаётся неразрешённым. Для числовых параметров это ошибка шага (unresolved_token) — мотор не выполняет действие с мусорным значением. Поэтому в демонстрационном рецепте размеры заданы числами, а {V:…} подключают, когда ментальные автоматизмы начнут писать в реестр.

Защита от задвоения команды оператора

Если мотор запущен тем же нажатием команды в SOLIDWORKS (например, вы сами нажали «Сохранить»), шаг run_sw_command с этим же кодом команды пропускается — иначе действие выполнилось бы дважды. Сравнение идёт только по числовому коду команды; параметры (для геометрии) на это не влияют.
