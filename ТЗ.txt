## ТЗ для VELUM-чата: подключение к каналу сокращённого лога ISIDA

### Что реализовано в `D:\Программы\ISIDA\Programms\isida` (движок)

**Новый файл:** `Common/ShortLogChannel.cs` — статический канал сокращённого (семантического) лога.

**API для записи (вызывать из кода движка в нужных местах):**

```csharp
// Один вызов = один токен с автовременем hh:mm:ss
ShortLogChannel.Write("Путь M (стадия 2)");

// Форматирование
ShortLogChannel.Write("Автоматизм: ID {0}, {1} (вес {2})", id, name, weight);

// Блок «заголовок + отступные строки» — всегда один токен
ShortLogChannel.WriteBlock("СТИМУЛ:", "Узел дерева автоматизмов: ID 15");
ShortLogChannel.WriteBlock("ОТВЕТ:", "Автоматизм: ID 3, Экспорт DXF (вес 2)");
```

**Границы сессии (автоматические):**
- `StartSession()` — вызывается в `GlobalTimer.Start()` при включении пульсации
- `StopSession()` — вызывается в `GlobalTimer.Stop()` и аварийных остановках при выключении
- `Reset()` — вызывается в `GlobalTimer.ClearSystems()` при выгрузке

**События для подписки клиента:**

| Событие | Параметр | Когда вызывается |
|---------|----------|------------------|
| `OnToken` | `ShortLogToken` | При каждом `Write`/`WriteBlock` |
| `OnSessionStarted` | `int sessionId` | При включении пульсации — клиент должен очистить вывод |
| `OnSessionCompleted` | `int sessionId, ShortLogToken[] tokens` | При выключении пульсации — все токены сессии |

**`ShortLogToken` содержит:**
- `Time` — `TimeSpan`, время создания (автоматически)
- `Text` — текст сообщения (может содержать `\n`)
- `SessionId` — идентификатор сессии
- `Pulse` — номер глобального пульса
- `ToString()` — готовое для отображения: `"13:16:22\nСТИМУЛ:\n  Узел..."`

### Что нужно изменить в VELUM

1. **Подписаться на события** `ShortLogChannel.OnToken`, `OnSessionStarted`, `OnSessionCompleted` при старте симбионта.
2. **При `OnSessionStarted`** — очистить текущий вывод сокращённого лога на клиенте.
3. **При `OnToken`** — вывести токен (`token.ToString()`) в панель сокращённого лога.
4. **При `OnSessionCompleted`** — зафиксировать конец сессии (опционально: сохранить в файл).
5. **Вкл/выкл отображения** — управляется через подписку/отписку от событий.
6. **Убедиться, что обработчики событий не блокируют поток пульса** — события вызываются вне блокировки, но исключений быть не должно (гасятся внутри `ShortLogChannel`).
7. **При выгрузке контекста** — отписаться от событий (сбросится при `ShortLogChannel.Reset()`).

### Пример использования в VELUM

```csharp
// В коде движка (ISIDA), в нужных местах:
ShortLogChannel.Write("Путь M (стадия 2)");
ShortLogChannel.WriteBlock("СТИМУЛ:",
    "Узел дерева автоматизмов: ID 15",
    "Тон: 0");
ShortLogChannel.WriteBlock("ОТВЕТ:",
    "Автоматизм: ID 3, Экспорт DXF (вес 2)");

// На клиенте (VELUM) при старте симбионта:
ShortLogChannel.OnSessionStarted += sessionId => {
    // Очистить вывод сокращённого лога
    ShortLogPanel.Clear();
};

ShortLogChannel.OnToken += token => {
    // Добавить токен в панель
    ShortLogPanel.AppendText(token.ToString());
};

Это надо использовать для сокращеных логов, которые выводятся в окно ответа агента в форме VelumAgentTaskPane. Текущее решение реализованное через класс VelumAgentCreationLogRules надо убрать. Теперь сокращенные логи будут читаться из движка
